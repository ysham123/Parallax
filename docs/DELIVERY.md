# Real-project delivery in 1.1

Project assessment reads bounded package manifests and instruction paths without executing project code. Team shows selected connection readiness, supported command isolation, package roots, proposed checks and explicit setup blockers. Saved project profiles contain workspace, package roots and check specifications; they are separate from team presets.

Build and Compare freeze the required checks before coordination. Every command has a relative cwd. Escaping paths, symlink package roots and unavailable command isolation are rejected. Discovery proposes npm script checks and Python unittest or pytest checks; explicit project commands remain available. Configure only meaningful, non-mutating verification. Ignored compiler output can be produced inside private workspaces.

A dedicated private baseline checkout runs the configured checks before assignment. Failed baseline checks are evidence for the requested repair, never permission to accept failing final checks. Resume reuses completed baseline evidence and reconciles interrupted managed processes before retrying incomplete checks. The combined candidate must pass every configured command with its original cwd and timeout, independent review, destination checks and the existing integration preservation gates. A coordinator cannot omit a required check in Build or Compare.

Python dependencies resolve in a run-private venv for each package and manifest digest. Node dependencies use npm ci with a committed lockfile and no lifecycle scripts. Each Node verification reprovisions from the current lockfile to avoid reusing stale modules after repairs. Private caches and homes stay outside the project. Runtime provenance records manifest hashes, whether a private Python venv was used, and the enforced sandbox. Manifest hashes do not prove identical resolution of unpinned Python dependencies.

Repair briefs carry the original user request, acceptance criteria, project instructions, independent findings, baseline results and actual failed final command output. Structured errors distinguish environment, provider access/permissions, rejected reviews, failed checks, destination conflicts, interrupted work and configuration limits. Studio's recovery choices preserve the candidate. Setup/specification changes start a new run; repair and interrupted retries resume through the existing action journal and cumulative budget. Conflict inspection does not overwrite user changes. Finalized candidates remain frozen.

CLI operations are assess, project-profiles, recover and feedback; MCP uses matching parallax_assess_project, parallax_project_profiles, parallax_save_project_profile, parallax_delete_project_profile, parallax_get_recovery, parallax_recover_run and feedback operations. All call the same authenticated local API. There are 24 MCP tools in 1.1. Assessment, project profiles and check evidence use version 1.1; RunSpec, RunEvent and RunResult accept 1.0 and 1.1. SQLite tables are additive. Existing immutable 1.0 receipts remain readable without being rewritten.

Linux execution requires working bubblewrap and unprivileged user namespaces. The CI workflow provisions bubblewrap before fake-provider tests. macOS uses the established Seatbelt policy and native CLI permission controls. Remote inference via a configured API is supported experimentally; SSH runners and remote mounts remain outside this release.
